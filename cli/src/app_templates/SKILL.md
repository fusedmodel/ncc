# {{title}}（NCC 舱）

这台机器上跑着一个**个人 Agent 舱**：内容住你自己（或团队）的 NCC 节点，互联走 ncc.ai 的身份与
点到点分享，**没有一份业务数据交给别人的云**。你（Agent）通过 NCC 的 CLI / MCP 用它。

## 先看清"这个舱有什么"

```bash
ncc app status --dir .      # 舱的现状：命名空间 / 入口 / 三样内容 / 出口 / 自检提醒
ncc app doctor --dir .      # 逐项自检（每项都带"下一步跑什么"）
```

对应到 MCP（把 `ncc mcp` 接进你的客户端即可）：

| 想干什么 | 工具 |
|---|---|
| 看舱里有哪些画布 / 笔记 | `ncc_list_kb`（关键词加权检索，不是向量） |
| 读一篇的正文（带 `checksum`，可自己核对） | `ncc_get_kb` |
| 读这个助理记得什么 | `ncc_list_mem` / `ncc_get_mem`（`subject = {{mem_subject}}`） |
| 看交接点 / 快照与血缘 | `ncc_list_ckpt` |
| 看出口被用了多少 | `ncc_list_gateways` / `ncc_gateway_audit` / `ncc_gateway_usage` |

## 三件你能做、也是"舱"的全部写动作

1. **读内容**（上面那些只读工具，随便用）。
2. **把一块内容变成一条链接发给人**：在控制台点「生成快照链接」，或让舱主人自己跑 ——
   生成的是**只读快照**（自包含 HTML），对方打开不需要账号；带 key 的链接要把 key 一起发。
   ⚠️ 这一步是**写动作**，工具面里没有：让用户自己点/自己跑（一次工具调用悄悄把内容发出去，是事故）。
3. **改内容**（写知识库、写记忆、打检查点）：一律由用户跑 CLI（`ncc kb set` / `ncc mem set` /
   `ncc ckpt save`）—— 让 Agent 悄悄改写主人的记忆，事后没人能复盘是谁改的。

## 边界（回答用户时要说清）

- **控制面只有摘要**：在线状态是控制面按心跳**推导**的，用量是网关**自报**的，签名只证明来源与完整。
  「谁调了哪个 URL」控制面答不了 —— 要去网关那台机器上跑 `ncc gateway audit`。
- **删舱 ≠ 删数据**：这个目录只是部署；内容（kb / mem / ckpt）在节点上，属于命名空间 `{{namespace}}`。
- **分享 ≠ 授权**：快照链接是临时的（可删）；要给人长期权限得用 `ncc grant`。
- 舱的控制台只监听本机（loopback）：它的界面不外露，"给别人看"走的是快照链接这一条路。
