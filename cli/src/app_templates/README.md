# {{title}}

这是一个 **NCC 舱**：你自己的一台机器 + 一份部署描述，就变成"记得住你、有自己一块工作台、
能安全地给别人看一部分"的个人 Agent 助理 —— 而内容与互联都**不用交给别人的云**。

```bash
ncc app doctor --dir .     # 逐项自检（缺什么、下一步跑什么，都会打出来）
ncc app up     --dir .     # 起舱：本机控制台 http://{{listen}}/
```

## 装在哪儿

| 东西 | 住在哪 | 谁看得到 |
|---|---|---|
| 画布 / 笔记（知识库 kb） | **节点**（`ncc-registry`），命名空间 `{{namespace}}` | 你自己 + 你授权的人 |
| 记忆（mem） | **节点**，`subject = {{mem_subject}}` | 只有你（记忆**没有公开档**，这是设计） |
| 检查点（ckpt） | **节点**，不可变快照 + 血缘 | 你自己 + 被授权的人 |
| 模型调用 | **你自己装的网关**（`ncc gateway`），路由 `{{route}}` | 控制面只看得到**摘要**（计数 / 主机名 / 分位） |
| 分享出去的那一份 | 云端 `ncc.ai`，一条**只读快照**链接 | 拿到链接（和 key）的人，**不需要账号** |

三条边界（很重要，别理解错）：

1. **控制面拿不到业务数据**：它看到的是摘要、身份、票据、授权关系。
2. **摘要 ≠ 完整审计**：网关侧的用量是**自报计数**，签名只证明"是持有那枚令牌的进程报的、没被改过"。
3. **删掉这个目录 ≠ 删数据**：内容在节点上，要单独删（`ncc kb rm` / `ncc mem rm` / `ncc ckpt rm`）。

## 别人怎么拿到一份一样的

```bash
ncc app export --dir . --out ../my-pod-export   # 生成可交付目录（含 sha256 清单）
```

对方在任何一台机器上：

```bash
ncc app doctor --dir my-pod-export
ncc app up     --dir my-pod-export
```

`app.json` 里的 `state.*` 是**指向**而不是副本 —— 所以换台机器部署同一份 `app.json`，
接上同一个命名空间，还是同一份内容。

## 文件

| 文件 | 是什么 |
|---|---|
| `app.json` | **部署描述**：这个舱叫什么、内容住哪个命名空间、出口走哪条路由、控制台听哪个端口 |
| `hur.json` | **应用逻辑**的包声明（合法 HUR 包）：`state{}` 要哪些状态、`egress{}` 要哪条出口、`security.entry` 怎么进来 |
| `SKILL.md` | 给 Agent 看的用法（这个产品怎么被 Agent 用） |
| `console.html` | 控制台页面（导出时才带上；平时由引擎内置的那份提供） |

`ncc app doctor` 会用**和 `ncc hur verify` 同一份判定**校验 `hur.json` —— 应用逻辑先得是个合法包。
